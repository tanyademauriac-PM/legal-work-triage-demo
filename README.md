# Work Triage Prototype

An interactive product-design prototype exploring how a case manager could recognize, prioritize, act on and track work without building a full case-management system first.

**[Read the product case study](https://tanyademauriac-pm.github.io/ai-product-portfolio/work-triage-prototype/)** · **[Open the live prototype](https://tanyademauriac-pm.github.io/legal-work-triage-demo/)**

## What to try

1. Review the **Needs attention** and **All tracked** lists. A due callback can require action while an unrelated document request on the same case is waiting.
2. Open **Casey** and confirm a documented receipt. This clears the missing-document signal without completing the paralegal's review.
3. Open **Devon** and request attorney review. The request is recorded as pending acceptance; no attorney acceptance or completion is simulated.
4. Inspect the **Operations** view. It reflects those recorded actions and responsibility states.
5. Use **Reset demo** to start again.

## Scope and boundaries

- All names, case values and records are fictional.
- Browser-only application with a fixed demo clock. It does not send messages, make calls or update real cases.
- Changes are intentionally not persistent and clear on refresh or Reset.
- Priorities are examples to test with users, not production policies.
- The prototype is intended to evaluate product assumptions **before** investment in integrations, access controls, durable records and a production workflow.

The private development project passed 30 automated functional tests. That does not constitute real-user validation.
